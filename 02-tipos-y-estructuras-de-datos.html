Los tres tipos básicos

El caso: una suma que falla

y   <- 10
num <- "42"
y + num
#> Error in y + num : argumento no-numérico para operador binario
  • Los dos «son 42 y 10» para ti
  • Para R, uno es un número y el otro es texto

Correrlo en vivo y dejar el error en pantalla. El mensaje de R es de los buenos: dice exactamente qué pasó.

Es el error que más aparece al leer un CSV en el que una columna traía un espacio o un guion, y por eso abre la unidad.

El #> marca lo que R contesta; no se escribe.

Qué tipo es cada cosa

class(num)
#> [1] "character"
class(y)
#> [1] "numeric"

num <- as.numeric(num)   # convertir el texto a número
y + num
#> [1] 52

class() es la función que más van a usar hoy. Y as.numeric() inaugura una familia entera: as.character(), as.logical(), as.factor().

Aviso que se paga solo: as.numeric("hola") devuelve NA con advertencia, no con error. Convertir a ciegas es cómo se pierden datos en silencio.

Los tres tipos

a  <- 5        # numérico
b  <- 3.14     # numérico
c2 <- 2e3      # numérico: 2000

x <- 5; y <- 10
x < y          # lógico: TRUE
x == y         # lógico: FALSE

nombre <- "Luis"     # carácter
curso  <- 'IntroR'   # las comillas simples son equivalentes

Ojo con c2 en vez de c: pisar c() es el error de nombres de la unidad 01 y aquí sería especialmente caro.

a <- 5 da "numeric", no "integer". Para un entero de verdad hace falta 5L, y aparece en la diapositiva de vectores.

Qué contesta class()

class(42)        #> "numeric"
class("42")      #> "character"
class(TRUE)      #> "logical"
class("TRUE")    #> "character"
class(42 > 10)   #> "logical"
class(NA)        #> "logical"

Con comillas es texto, siempre. Da igual que dentro haya un número o la palabra TRUE.

Recorrer los seis en voz alta y preguntar cuáles se parecen sin ser lo mismo: son 1–2 y 3–4. La quinta es la interesante, porque una comparación devuelve un lógico en vez de escribirlo uno. Y class(NA) da "logical", que sorprende; no hace falta explicarlo hoy, basta con que vean que NA también tiene tipo.

Esa regla —«con comillas es texto»— es la que resuelve el 90 % de los problemas de tipos que van a tener con datos reales.

Los tres errores clásicos

"42" + 10          # 1. operar entre tipos incompatibles -> Error

logico <- TRUE     # 2. "logical"
texto  <- "TRUE"   #    "character" — no es lo mismo

nombre <- Luis     # 3. sin comillas -> Error: objeto 'Luis' no encontrado

Ese matiz del tercer caso es el que convierte un error en un bug: sin comillas, R busca un objeto. Si no existe, avisa; si existe, obedece.

Practica · arregla el error

Este bloque no corre. Arréglalo sin borrar ninguna línea:

edad <- "45"
peso <- 78
imc_aprox <- peso / edad
  • Pista 1: primero averigua qué tipo es cada variable
  • Pista 2: la solución es una línea más, no cambiar las comillas

Cinco minutos. La solución es edad <- as.numeric(edad) antes de la división.

Si alguien quita las comillas de "45", también funciona — y es buen momento para decir que en datos reales no puedes: el texto viene así del archivo.

Lo que acabas de usar es una función

class() y as.numeric() son funciones: bloques de código con nombre que hacen una tarea y se reutilizan.

  • Se reconocen por los paréntesis después del nombre
  • ?nombre te dice qué argumentos acepta — unidad 01

El class() de R está escrito en C: R_data_class, en src/main/attrib.c del código fuente

Hoy solo se usan funciones; escribirlas es de otro curso. Pero conviene nombrar la idea ahora, porque a partir de aquí todo lo que hacen es llamar funciones.

Vectores

Un vector es una fila de casilleros

Una colección ordenada de elementos del mismo tipo.

v_num <- c(1, 2, 3, 4.5)
v_int <- c(1L, 2L, 3L)        # la L fuerza un entero de verdad
v_log <- c(TRUE, FALSE, TRUE)
v_chr <- c("a", "b", "c")

Del mismo tipo no es un detalle: es la definición. c() viene de combine.

Qué pasa si mezclas tipos

c(1, 2, "tres")
#> [1] "1"    "2"    "tres"

c(TRUE, FALSE, 3)
#> [1] 1 0 3
  • R no da error: convierte al tipo que lo admite todo
  • Se llama coerción: lógico → numérico → carácter

Esta diapositiva no está en el material original y es la que más problemas ahorra: la coerción silenciosa es la causa número uno de «me sale error y no entiendo por qué» al leer datos reales.

Tus números se volvieron texto sin avisar, y el sum() falla tres líneas más abajo de donde se cometió el error.

Practica · la coerción

Antes de correr cada línea, escribe qué crees que va a pasar:

  1. class(c(1, 2, 3))
  2. class(c(1, 2, "3"))
  3. sum(c(1, 2, 3))
  4. sum(c(1, 2, "3"))
  5. class(c(TRUE, 1))

Solo una de las cinco da error. ¿Cuál esperabas?

Cuatro minutos. Predecir antes de correr es la mitad del ejercicio: si no lo piden, copian y pegan sin mirar.

La 4 es la que falla, y la 2 es la que explica por qué. Ese par es la lección.

Practica · respuestas

class(c(1, 2, 3))      #> "numeric"
class(c(1, 2, "3"))    #> "character"   <- se coló un texto
sum(c(1, 2, 3))        #> 6
sum(c(1, 2, "3"))      #> Error: 'type' (character) de argumento no válido
class(c(TRUE, 1))      #> "numeric"     <- TRUE se volvió 1

Regla práctica: si un sum() falla sin motivo aparente, class() al vector antes que nada.

El error de la línea 4 aparece lejos de donde está el problema, que es la línea 2. Es exactamente lo que pasa con un CSV mal leído.

Nombres e indexación

Ponerle nombre a cada casillero

Casos confirmados en seis estados. Los números solos no dicen de quién son.

casos_marzo <- c(1200, 850, 430, 670, 1500, 920)
names(casos_marzo) <- c("CDMX", "Jalisco", "Yucatan",
                        "Puebla", "NuevoLeon", "Chiapas")
casos_marzo
#>      CDMX   Jalisco   Yucatan    Puebla NuevoLeon   Chiapas
#>      1200       850       430       670      1500       920

Aquí se cierra lo que quedó pendiente en la unidad 01: doce variables sueltas, ahora dos vectores.

names() no junta dos vectores

  • Le pega una etiqueta a cada posición del vector que ya existe
  • Los datos son exactamente los mismos que antes
  • names es un atributo del vector, no una segunda columna

Y sirve para leer: casos_marzo["Puebla"] devuelve 670, sin contar posiciones.

El malentendido de names() está anticipado en el material original y vale la pena atajarlo: creen que ahora hay dos columnas. No las hay.

Cuatro formas de seleccionar

defunciones_marzo <- c(50, 40, 12, 25, 65, 30)

defunciones_marzo[1]                        #> 50          por posición
defunciones_marzo[c(2, 5)]                  #> 40 65       varias
defunciones_marzo[-3]                       #> 50 40 25 65 30
defunciones_marzo[defunciones_marzo > 30]   #> 50 40 65    por condición

En R los índices empiezan en 1, no en 0.

El [-3] sorprende a todo el mundo: en R el índice negativo excluye, no cuenta desde el final.

La cuarta forma es la importante. Se usa el resto de la unidad y del curso.

Practica · selecciona

Con casos_marzo, el vector con nombres:

  1. El valor de Jalisco, por nombre
  2. El valor de Jalisco, por posición
  3. Los tres primeros estados
  4. Todos menos el primero
  5. Los estados con más de 1 000 casos
  6. ¿Cuántos estados cumplen la condición 5?

Seis minutos. Es la práctica central de la parte A.

La 6 se resuelve con length() alrededor de la 5, o con sum() sobre el vector lógico —que es lo que se explica en la diapositiva siguiente— . Las dos respuestas valen.

Practica · respuestas

casos_marzo["Jalisco"]              #> 850
casos_marzo[2]                      #> 850
casos_marzo[1:3]                    #> CDMX Jalisco Yucatan
casos_marzo[-1]                     #> todos menos CDMX
casos_marzo[casos_marzo > 1000]     #> CDMX 1200, NuevoLeon 1500
length(casos_marzo[casos_marzo > 1000])   #> 2

Los nombres viajan con los datos a través del filtro. Por eso valía la pena ponerlos.

Subrayar eso último: no hubo que volver a decir qué estado era cada número.

La cuarta es la que importa

casos_marzo > 1000
#>      CDMX   Jalisco   Yucatan    Puebla NuevoLeon   Chiapas
#>      TRUE     FALSE     FALSE     FALSE      TRUE     FALSE
  • La condición no devuelve los datos: devuelve TRUE/FALSE
  • Ese vector es lo que va dentro de los corchetes
  • R se queda con las posiciones que valen TRUE

Correrlo en dos pasos en vivo: primero la condición sola, después dentro de los corchetes. Si se ve el vector lógico intermedio, todo lo que viene después se explica solo — y es lo que hace que las matrices sean fáciles en vez de mágicas.

Practica · la condición, en dos pasos

  1. Corre solo casos_marzo > 1000. ¿Qué tipo de vector es?
  2. Guárdalo en una variable llamada muchos
  3. Ahora corre casos_marzo[muchos]
  4. Corre sum(muchos). ¿Por qué da un número?

Cinco minutos. El paso 2 —guardar el vector lógico en su propia variable— es la técnica de depuración de toda la unidad: cuando una selección devuelve algo raro, se imprime la condición por separado.

sum(muchos) da 2: cuenta cuántos TRUE hay. Enlaza con la coerción de hace media hora.

No adelantar el porqué del punto 4: que lo corran y lo vean primero. La frase, para decirla después de que hayan probado, es que TRUE vale 1 y FALSE vale 0, y que ese truco se usa constantemente.

Operaciones con vectores

Operar sobre el vector entero

casos_enero <- c(3000, 1500, 1200, 1800, 2500, 2100)
names(casos_enero) <- names(casos_marzo)

casos_enero + casos_marzo
#>      CDMX   Jalisco   Yucatan    Puebla NuevoLeon   Chiapas
#>      4200      2350      1630      2470      4000      3020
  • R suma posición por posición, sin que escribas un ciclo

Se llama vectorización y es la razón de que R sea cómodo con datos.

Quien haya programado en otro lenguaje espera un for. En R casi nunca hace falta.

Operar, o resumir

sum(casos_enero)    #> 12100
mean(casos_enero)   #> 2016.667
min(casos_marzo)    #> 430
max(casos_marzo)    #> 1500
Devuelve
Elemento a elemento (+, *, >) un vector del mismo largo
Agregación (sum, mean, min, max) un solo número

La distinción entre las dos familias ordena todo el bloque. Si la tienen clara, colSums() y rowSums() de la parte B no necesitan explicación.

¿Y si no miden lo mismo?

Solo dos estados mandaron el reporte de abril:

casos_abril <- c(CDMX = 1300, Jalisco = 900)

casos_marzo + casos_abril
#>      CDMX   Jalisco   Yucatan    Puebla NuevoLeon   Chiapas
#>      2500      1750      1730      1570      2800      1820

R no da error. Pero Yucatán lleva sumados los casos de CDMX, y Puebla los de Jalisco: cuatro de los seis números son inventados.

Proyectarla y callarse unos segundos antes de explicar. Todo se ve bien: seis estados, nombres correctos, cifras plausibles. Esa es la trampa.

Los nombres los pone el vector largo, así que la etiqueta te confirma un resultado que no existe.

La regla del reciclado

R repite el vector corto hasta emparejar al largo:

CDMX Jalisco Yucatán Puebla N. León Chiapas
casos_marzo 1200 850 430 670 1500 920
casos_abril 1300 900 1300 900 1300 900
suma 2500 1750 1730 1570 2800 1820

En cursiva, lo que R repitió sin pedirlo. En negrita, los cuatro resultados falsos. El resultado tiene siempre el largo del vector más largo.

Tu vector de dos estados se convirtió en uno de seis sin que lo pidieras.

Decirlo con estas palabras: R hace algo razonable sin que se lo pidas, y esa es justo la parte peligrosa.

Enlace que cierra el concepto: casos_marzo * 2 es el mismo reciclado. El 2 es un vector de largo 1 que se repite seis veces. O sea que llevan todo el bloque reciclando sin saberlo; el problema no es el reciclado, es no verlo.

El caso peligroso es el que no avisa

c(1, 2, 3) + c(1, 2, 3, 4, 5)
#> Warning: longitud de objeto mayor no es múltiplo de la longitud de uno menor

c(1, 2, 3) + c(1, 2, 3, 4, 5, 6)
#> [1] 2 4 6 5 7 9      <- ni una palabra

El aviso salta solo si el largo mayor no es múltiplo del menor. Antes de operar dos vectores: length() a los dos.

6 sobre 2, 200 sobre 100, 12 sobre 6: los múltiplos son justo el caso frecuente con datos reales. El silencio no es la excepción, es lo normal.

Y una advertencia tampoco detiene el cálculo: R igual entrega un resultado. Si el aviso aparece, la respuesta está mal aunque se vea bien.

Matrices

Cuando una fila de casilleros no basta

Cuatro alimentos, cuatro variables cada uno. Por 100 g:

kcal Carbohidratos Proteínas Grasas
Manzana 52 14 0.3 0.2
Pollo 165 0 31 3.6
Arroz 130 28 2.7 0.3
Frijoles 127 23 9 0.5
  • Con vectores harían falta cuatro, y perderías que cada fila es un alimento

El límite del vector es real: se puede hacer con cuatro vectores, pero la relación entre ellos deja de estar en los datos y pasa a estar en tu cabeza.

Una matriz es una tabla: filas, columnas, un solo tipo de dato.

R llena las matrices por columnas

matrix(1:9, nrow = 3, ncol = 3)
#>      [,1] [,2] [,3]
#> [1,]    1    4    7
#> [2,]    2    5    8
#> [3,]    3    6    9

El 1, 2, 3 quedó en la primera columna, no en la primera fila.

Detenerse aquí. Casi todo el mundo espera 1 2 3 en la primera fila. Si no se señala, arrastran el malentendido hasta la matriz de nutrientes, donde el error ya no es evidente porque los números no están ordenados.

Practica · ¿dónde cae el 4?

  1. Antes de correrlo: ¿dónde crees que cae el 4 en matrix(1:12, nrow = 3, ncol = 4)?
  2. Córrelo y compruébalo
  3. Ahora corre lo mismo añadiendo byrow = TRUE. ¿Qué cambió?

Tres minutos. Predecir antes de correr, otra vez: si no lo piden, no piensan.

El 4 cae en la fila 1, columna 2 sin byrow, y en la fila 2, columna 1 con él. Verlo así deja el concepto cerrado.

byrow = TRUE: llenar como se lee

manzana <- c(52, 14, 0.3, 0.2);  pollo  <- c(165, 0, 31, 3.6)
arroz   <- c(130, 28, 2.7, 0.3); frijol <- c(127, 23, 9, 0.5)

nutricion_matrix <- matrix(c(manzana, pollo, arroz, frijol),
                           nrow = 4, byrow = TRUE)

Cada vector es un alimento, así que hay que llenar por filas. Sin byrow la matriz sale transpuesta y con el sentido físico equivocado.

Sin byrow, la primera columna sería «manzana» y la primera fila «calorías de los cuatro». Aquí se paga haber entendido la diapositiva anterior.

Nombres de filas y de columnas

colnames(nutricion_matrix) <- c("Calorias", "Carbohidratos",

#> Pollo         165             0      31.0    3.6

#> Frijoles      127            23       9.0    0.5

En vectores era names(). En matrices no: hay dos dimensiones y hay que decir cuál. Intentar names(matriz) <- ... no falla con un mensaje claro; simplemente no hace lo que se espera.

& (Y) las dos · | (O) al menos una · ! (NO) invierte. Mira la primera fila: el | de R es inclusivo, TRUE | TRUE da TRUE.

Recorrer la tabla fila por fila, en voz alta. La que hay que señalar es la primera: en castellano «o» se oye muchas veces como «uno u otro, no los dos», y el | de R incluye el caso de que se cumplan las dos.

Guardar las condiciones aparte no es estilo: sin esa técnica, cuando una selección compuesta devuelve algo raro no hay forma de saber cuál de las dos falló.

Precedencia, por si alguien encadena tres: primero !, luego &, luego |. Así que a | b & c se lee a | (b & c). Con más de dos condiciones, paréntesis.

&& no es lo mismo que &. Quien venga de otro lenguaje va a escribir &&, que solo admite un valor: sobre vectores da Error: 'length = 2' in coercion to 'logical(1)'. Para seleccionar filas, siempre & y | sencillos.

Factores

Un factor es un vector que solo puede contener valores predefinidos. Se usa para guardar datos categóricos. Los factores se construyen sobre un vector de enteros con dos atributos: una clase, "factor", que hace que se comporte distinto de los vectores de enteros normales, y unos niveles (levels), que definen el conjunto de valores permitidos.

Wickham (2019), Advanced R, 2.ª ed., §3.4.1 · CC BY-NC-SA 4.0 · traducción propia

Es la definición de Advanced R (Wickham, 2.ª ed., §3.4.1), traducida. Leerla completa y quedarse en la figura: arriba, los números que se guardan; abajo, los dos atributos pegados al vector.

La figura es factor(c("a", "b", "b", "a")): los enteros 1 2 2 1 apuntan a los niveles “a” y “b”. «Atributo» ya apareció con names: información extra que viaja con el vector.

Las dos primeras frases dicen qué representa un factor, una variable categórica; la tercera, cómo lo guarda R. «Lo que se ve y lo que se guarda» lo enseña en código.

El original: «A factor is a vector that can contain only predefined values. It is used to store categorical data. Factors are built on top of an integer vector with two attributes: a class, “factor”, which makes it behave differently from regular integer vectors, and levels, which defines the set of allowed values.»

Dónde está el factor entre los vectores

  • En negro, los tipos básicos; integer y double son los numéricos
  • En azul, lo que se construye encima de un tipo básico, con atributos
  • factor está sobre integer; las fechas, Date y POSIXct, sobre double

Figura: Wickham (2019), Advanced R, 2.ª ed., §3.4 · CC BY-NC-SA 4.0 · redibujada

Es la figura de Advanced R (§3.4). Responde a la pregunta de si el factor es una estructura aparte: por dentro es un vector de enteros, y lo que lo vuelve factor son sus atributos. Por eso, en «Lo que se ve y lo que se guarda», typeof() dice "integer" y class() dice "factor".

Las fechas usan el mismo truco, sobre double.

El libro llama a los azules «vectores S3». No hace falta decir S3 en clase: basta con «un tipo básico con atributos».

Cuando el texto es en realidad una categoría

La columna Grupo del data frame es texto. Pero no es texto: es una categoría.

nutricion_df$Grupo <- factor(nutricion_df$Grupo)

nutricion_df$Grupo
#> [1] Fruta  Proteína  Carbohidrato  Legumbre  Proteína  Legumbre
#> Levels: Carbohidrato Fruta Legumbre Proteína

Un factor es un vector para datos categóricos. Los niveles son las categorías que R encontró; por dentro guarda enteros y una tabla de equivalencias.

Si «Proteína» se repite mil veces, guardar mil textos es caro. Guardar mil veces el número 3, y una vez la palabra, no.

Aviso por si encuentran tutoriales viejos: desde R 4.0 read.csv() ya no convierte el texto en factor. Ahora llega como character y el factor lo creas tú cuando lo necesitas.

Los datos y el catálogo

sev <- c("grave", "leve", "leve", "moderado", "leve")
table(sev)       #> grave 1   leve 3   moderado 1

f <- factor(sev, levels = c("leve", "moderado", "grave", "muy grave"))
table(f)
#>      leve  moderado     grave muy grave
#>         3         1         1         0

Mismos cinco datos. El factor contiene los datos (length(f) es 5) y además conoce las respuestas posibles (nlevels(f) es 4).

Dos cosas cambian entre las tablas: el orden pasa a ser el clínico, y aparece «muy grave» con cero. Ese cero es información: en esta muestra no hubo ningún caso muy grave. El texto no puede decirlo porque nunca supo que esa respuesta existía.

La confusión que hay que atajar: el factor no «contiene las respuestas posibles». Contiene a los cinco pacientes y, además, sabe cuáles eran las cuatro respuestas.

summary() de una matriz numérica daba cuartiles. De un factor da un conteo. La misma función se comporta según lo que le des.

Ese comportamiento —una función que se adapta al tipo del objeto— es una idea grande de R y aquí aparece por primera vez de forma visible.

Lo que se ve y lo que se guarda

f <- factor(c("Grave", "Leve", "Moderado", "Leve"))

typeof(f)              #> "integer"
class(f)               #> "factor"
names(attributes(f))   #> "levels" "class"

Tres piezas: los códigos enteros, el catálogo (levels) y la etiqueta (class) que le dice a R que busque cada código en el catálogo.

El entero no es arbitrario: es la posición en el catálogo. Ahí vive el orden, y es la forma de apuntar a un catálogo que existe aparte de los datos.

Ahorrar memoria es un motivo secundario: con 100 000 valores de cuatro categorías, el factor ocupa la mitad que el texto, no mucho menos.

Y factor() ordena el catálogo, no los datos: el primer paciente sigue siendo el primero.

Declarar el orden: levels y relevel()

x <- c("grave", "leve", "moderado", "leve")

levels(factor(x))                            #> grave leve moderado
levels(factor(x, levels = c("leve", "moderado", "grave")))
#> leve moderado grave

levels(relevel(factor(x), ref = "leve"))     #> leve grave moderado

Un valor que no esté en levels se vuelve NA. Antes de declarar, mira qué hay con unique(x): un «Leve» con mayúscula basta para perder datos.

Los datos no se mueven: solo cambia el catálogo.

relevel() mueve una sola categoría al principio y deja el resto como estaba. Sirve para elegir la categoría de referencia de un modelo, que se ve más adelante.

Categorías que tienen orden

porciones <- c("Mediana", "Pequeña", "Grande", "Mediana", "Pequeña")

factor_porciones <- factor(porciones,
                           levels = c("Pequeña", "Mediana", "Grande"),
                           ordered = TRUE)
factor_porciones
#> Levels: Pequeña < Mediana < Grande

Ahora R entiende la jerarquía, y factor_porciones[1] > factor_porciones[2] —Mediana contra Pequeña— devuelve TRUE.

En ciencias de la salud esto es constante: leve < moderado < grave, o los estadios de una clasificación clínica.

El orden alfabético es una trampa

Sin levels, R ordena alfabéticamente: Grande < Mediana < Pequeña. Que es justo al revés.

  • El factor queda ordenado y las comparaciones funcionan
  • El resultado está invertido y nada avisa

Es de los errores que no producen ningún mensaje y sobreviven hasta la gráfica final, donde las categorías salen al revés y nadie sabe por qué.

levels ordena, ordered compara

Argumento Qué decide Para qué sirve
levels = c(...) el orden de las categorías tablas, gráficas y referencia
ordered = TRUE si se pueden comparar con < y > escalas con jerarquía real

Son independientes. Para filtrar basta ==, que funciona siempre; ordered solo hace falta para preguntar «mayor que».

Sin ordered, f[1] > f[2] devuelve NA con el aviso «‘>’ no es significativo para factores». Con ordered = TRUE funcionan >, <, min() y max().

Conviene decirlo: sort() y table() respetan el orden de levels aunque el factor no sea ordenado. Con las porciones, el texto ordena Grande, Mediana, Pequeña; el factor, Pequeña, Mediana, Grande, con o sin ordered.

Cerrado no implica ordenado: fruta, legumbre y proteína forman un conjunto cerrado sin jerarquía.

De números a categorías: cut()

edad <- c(23, 37, 45, 61, 72, 58)

    labels = c("18-39", "40-59", "60+"), right = FALSE)
#> [1] 18-39 18-39 40-59 60+   60+   40-59
#> Levels: 18-39 40-59 60+

right = FALSE incluye el límite inferior: alguien de 40 años cae en «40-59». Los cortes se deciden por criterio clínico, antes de mirar los datos.

Grupos de edad, categorías de IMC, rangos de presión arterial: muchas variables categóricas de salud nacen de números.

Con ordered_result = TRUE el resultado es un factor ordenado.

Recordatorio: aunque los grupos tengan orden, promediar categorías no tiene sentido, porque las distancias entre niveles no son iguales.

Para qué sirve de verdad un factor

  • lm() y glm() generan automáticamente el análisis por grupo
  • ggplot2 le da un color, una faceta o una caja a cada nivel
  • El orden de los niveles decide el orden en tablas y gráficas

Este es el argumento que hace que no lo vean como burocracia. En sus tesis van a correr modelos: si la variable de grupo no es factor, el modelo la trata como número y el resultado no significa nada.

Decirle a R qué significa cada código

levels dice qué códigos existen y en qué orden; labels dice cómo se llama cada uno, en ese mismo orden.

Es el labels de cut(), ahora dentro de factor().

El orden de labels tiene que seguir al de levels: si se invierten, las madres que fumaron quedan etiquetadas como «no fumó» y R no avisa.

El mismo grupo, dos modelos

# bwt: peso al nacer, en gramos · race: 1 = blanca, 2 = negra, 3 = otra
coef(lm(bwt ~ race, data = MASS::birthwt))
#> (Intercept) 3230   race -155
nacimientos$race <- factor(nacimientos$race, levels = 1:3,
                           labels = c("blanca", "negra", "otra"))
coef(lm(bwt ~ race, data = nacimientos))
#> (Intercept) 3103   racenegra -383   raceotra -297

Con los códigos, lm() ajusta una pendiente que supone distancias iguales entre grupos. Como factor, compara cada grupo con el primero, «blanca».

Mismos datos, dos resultados incompatibles, y la diferencia es una línea.

Lectura del segundo: los bebés de madres blancas pesaron 3103 g en promedio; los de madres negras, 383 g menos, y los del grupo «otra», 297 g menos. Eso sí se reporta, como diferencia sin ajustar. La pendiente de −155 g «por grupo» no significa nada: supone que «otra» está al doble de distancia que «negra».

race es la clasificación del estudio original (Estados Unidos, 1986); se usa tal como viene en el diccionario de datos.

Es la primera viñeta de «Para qué sirve de verdad un factor», ahora con números.

Qué entendió lm() en cada modelo

Con los códigos, race es un número y hay una sola pendiente:

\[\text{bwt} = 3230 - 155 \cdot \text{race}\]

Cada paso, de 1 a 2 y de 2 a 3, resta lo mismo: 155 g.

Como factor, cada grupo tiene su propio coeficiente:

\[\text{bwt} = 3103 - 383 \cdot \text{negra} - 297 \cdot \text{otra}\]

negra y otra valen 1 o 0. En «blanca» las dos valen 0: por eso 3103 es su promedio.

Con los códigos, R traza una recta entre los grupos. Como factor, le da a cada grupo su promedio.

La idea, sin notación: con números, R traza una recta que pasa por los tres grupos; con el factor, le da a cada grupo su promedio.

Con los códigos, el modelo supone que pasar de «blanca» (1) a «negra» (2) cambia el peso lo mismo que pasar de «negra» (2) a «otra» (3). Por eso predice para «negra» 3230 − 155 × 2, unos 2921 g, cuando su promedio real es 2720 g. Los grupos son etiquetas, no cantidades.

Como factor, R convierte race en variables indicadoras (dummy): una por cada grupo que no es la referencia, con valores 0 o 1. El intercepto, 3103, es el promedio de «blanca»; −383 y −297 son lo que se aleja de «blanca» cada grupo. Con el factor, «negra» da 3103 − 383 = 2720: su promedio exacto.

Por si alguien pide la forma general: bwt = β₀ + β₁ · race, contra bwt = β₀ + β_negra · I(negra) + β_otra · I(otra). Los coeficientes de la diapositiva están redondeados al gramo.

La categoría de referencia

coef(lm(bwt ~ smoke, data = nacimientos))
#> (Intercept) 3056   smokefumó -284

nacimientos$smoke <- relevel(nacimientos$smoke, ref = "fumó")
coef(lm(bwt ~ smoke, data = nacimientos))
#> (Intercept) 2772   smokeno fumó 284

La primera categoría es la referencia. Las medias no cambian; cambia contra quién se compara.

Medias: 3056 g con madres que no fumaron y 2772 g con madres que fumaron.

Primera salida: «los bebés de madres que fumaron pesaron 284 g menos». Segunda: «los de madres que no fumaron pesaron 284 g más». Es la misma diferencia; se reporta la primera, porque la referencia debe tener sentido clínico: control, placebo, la categoría leve, los no expuestos.

Por eso en «Decirle a R qué significa cada código» se puso primero el 0. Y amarra con «La misma tabla, antes y después»: ahí había más bajo peso entre las que fumaron; el modelo lo dice en gramos. Sigue siendo una diferencia sin ajustar.

Para regresar la referencia: relevel(nacimientos$smoke, ref = "no fumó").

Por qué es el mismo modelo

Con «no fumó» como referencia:

\[\text{bwt} = 3056 - 284 \cdot \text{fumó}\]

Con «fumó» como referencia:

\[\text{bwt} = 2772 + 284 \cdot \text{no fumó}\]

Sustituye 0 y 1: las dos ecuaciones dan 3056 g sin fumar y 2772 g fumando. Mismos promedios; solo cambia desde qué grupo se mide la diferencia.

Hacerlo en voz alta. En la primera: sin fumar, fumó vale 0 y queda 3056; fumando vale 1, y queda 3056 − 284 = 2772. En la segunda: fumando, no fumó vale 0 y queda 2772; sin fumar vale 1, y queda 2772 + 284 = 3056.

relevel() no cambia el ajuste: las mismas predicciones, los mismos residuos y el mismo R². Cambia solo cómo se escribe el modelo, es decir, contra quién se mide cada coeficiente.

Se reporta la versión con la referencia que tiene sentido clínico: «no fumó».

Listas

Una lista es un contenedor que guarda objetos de cualquier tipo y cualquier largo, cada uno en su propio compartimento.

Decirla tal cual. La palabra clave es «cualquier»: un vector exige un solo tipo, una matriz exige un tipo y dos dimensiones, un data frame exige columnas del mismo largo. La lista no exige nada.

Es el último escalón de la unidad, y por eso el más flexible.

La figura pone juntas las estructuras de la unidad. En la lista, cada compartimento guarda una distinta: un vector, una matriz, un data frame y un solo dato.

Cuatro cosas que no caben juntas

Un brote en investigación: un nombre, una tabla de casos, quién tuvo contacto con quién y si el brote sigue activo.

datos_casos <- data.frame(
  ID_Caso       = c("C01", "C02", "C03"),
  Edad          = c(25, 42, 31),
  Hospitalizado = c(FALSE, TRUE, FALSE)
)
matriz_contactos <- matrix(c(0, 1, 1, 1, 0, 0, 1, 0, 0), nrow = 3)

Un texto, un data frame, una matriz y un lógico: ni un vector, ni una matriz, ni un data frame pueden guardar las cuatro cosas juntas.

Preguntarlo antes de pasar a la siguiente: ¿en qué estructura de las que ya conocen guardarían estas cuatro cosas? Que las descarten una por una.

Un vector no: los tipos son distintos. Una matriz tampoco, por lo mismo. Un data frame no: las piezas no miden lo mismo.

Cuando nada de lo anterior cabe

Cada pieza entra en su compartimento con un nombre: nombre = objeto.

investigacion_brote <- list(
  Nombre    = "Nuevo brote",       # texto de largo 1
  Datos     = datos_casos,         # un data frame de 3 x 3
  Contactos = matriz_contactos,    # una matriz de 3 x 3
  Activo    = TRUE                 # un lógico de largo 1
)

Un data frame exige que todas las columnas midan lo mismo. Una lista, no.

El argumento definitivo: cuando corran lm() en su tesis, lo que devuelve es una lista. Saber sacarle elementos es lo que permite usar el resultado.

Mirar una lista

length(investigacion_brote)   #> 4
names(investigacion_brote)    #> "Nombre" "Datos" "Contactos" "Activo"
str(investigacion_brote)
#> List of 4
#>  $ Nombre   : chr "Nuevo brote"
#>  $ Datos    :'data.frame':  3 obs. of  3 variables:
#>  $ Contactos: num [1:3, 1:3] 0 1 1 1 0 0 1 0 0
#>  $ Activo   : logi TRUE

length() cuenta compartimentos, no datos: el data frame entero cuenta como uno solo.

str() vuelve a ser lo primero que hay que teclear: dice cuántos elementos hay, cómo se llaman y de qué tipo es cada uno.

En la consola, str() también despliega las tres columnas del data frame; aquí va abreviada.

Sacar cosas de una lista

Analogía del tren: Wickham (2019), Advanced R, 2.ª ed., §4.3.1

Es la distinción que más tiempo hace perder a quien empieza. La analogía es de Advanced R: cada objeto es un tren, cada elemento es un vagón y lo que va dentro son sus pasajeros.

Arriba, el data frame que ya conocen. datos_casos["Edad"] desengancha un vagón y devuelve un tren más corto: sigue siendo un data frame. Con la coma, datos_casos[, "Edad"] baja a los pasajeros: el vector 25, 42, 31. La coma funciona porque todos los vagones llevan el mismo número de pasajeros: hay filas.

Abajo, la lista. Cada vagón lleva algo distinto, así que no hay filas ni coma. investigacion_brote["Nombre"] sigue siendo un tren; para bajar al pasajero hace falta [["Nombre"]].

Que lo comprueben en R: class(investigacion_brote["Nombre"]) da "list" y class(investigacion_brote[["Nombre"]]) da "character". Si alguien prueba la coma, investigacion_brote[, "Nombre"] da el error «número incorreto de dimensiones» (así, con la errata de la traducción de R).

En el data frame también funcionan datos_casos[["Edad"]] y datos_casos$Edad: en «El data frame es una lista» se verá por qué.

Un corchete de menos

investigacion_brote[["Datos"]]$Edad    #> 25 42 31
investigacion_brote["Datos"]$Edad      #> NULL

mean(investigacion_brote["Datos"]$Edad)
#> NA
#> Warning: argument is not numeric or logical: returning NA

Con un solo corchete sacas una caja que contiene el data frame, y esa caja no tiene ningún compartimento llamado Edad. R no da error: devuelve NULL.

Es el tropiezo más frecuente con listas, y no se nota en el momento: el problema aparece una línea después, cuando mean() recibe algo vacío.

El aviso sale en inglés aunque R esté en español: ese mensaje no tiene traducción.

Si alguien ve un NULL donde esperaba datos, la primera pregunta es: ¿cuántos corchetes pusiste?

$: el atajo por nombre

investigacion_brote$Nombre    #> "Nuevo brote"
investigacion_brote$Nom       #> "Nuevo brote"   <- basta con el principio
investigacion_brote$Fecha     #> NULL            <- no existe, y no avisa

$ equivale a [[ ]] con el nombre: saca lo que hay dentro. Es el mismo $ de los data frames.

Que $Nom funcione es cómodo en la consola y peligroso en un script: si la lista llega a tener otro elemento que empiece igual, deja de funcionar. En los scripts, nombres completos.

El NULL de un nombre que no existe es el mismo silencio de la diapositiva anterior: revisar la ortografía antes que el código.

Por posición, y con el nombre en una variable

class(investigacion_brote[[2]])        #> "data.frame"

campo <- "Datos"
class(investigacion_brote[[campo]])    #> "data.frame"
investigacion_brote$campo              #> NULL   <- busca un elemento «campo»

[[ ]] acepta una posición o un nombre guardado en una variable. $ solo acepta el nombre escrito tal cual.

Por posición funciona, pero es frágil: si alguien añade un elemento antes, la posición 2 ya es otra cosa. Por nombre es más seguro.

El caso de la variable aparece en cuanto recorran varias listas o varias columnas con el mismo código.

Cajas dentro de cajas

investigacion_brote$Datos$Edad[2]          #> 42
investigacion_brote$Contactos[2, 3]        #> 0
investigacion_brote[["Datos"]][["ID_Caso"]][3]
#> "C03"

Se lee de izquierda a derecha, abriendo una caja cada vez: primero la lista, luego el data frame, luego la columna, luego la posición.

Descomponer la primera línea en voz alta: investigacion_brote$Datos es el data frame; $Edad es su columna; [2] es el segundo valor.

Cada estructura conserva su propia forma de seleccionar: la matriz de contactos se sigue indexando con [fila, columna] aunque viva dentro de una lista.

Añadir y cambiar elementos

investigacion_brote$Fecha <- "2026-09-17"   # añadir: un nombre nuevo
length(investigacion_brote)                 #> 5

investigacion_brote$Activo <- FALSE         # cambiar: un nombre que ya existe
investigacion_brote$Activo                  #> FALSE

La misma línea añade o cambia: si el nombre existe, lo sustituye; si no, crea un compartimento nuevo al final.

Es la misma sintaxis que añadir una columna a un data frame con $, y por la misma razón: un data frame es una lista, como se verá más adelante.

A diferencia del data frame, aquí no hay que respetar ningún largo: el elemento nuevo puede ser cualquier cosa.

Quitar un elemento: NULL

investigacion_brote$Activo <- NULL
length(investigacion_brote)    #> 4
names(investigacion_brote)     #> "Nombre" "Datos" "Contactos" "Fecha"

Asignar NULL borra el compartimento, no lo vacía: lo que había ahí se pierde.

Tras añadir Fecha y quitar Activo, la lista vuelve a tener cuatro elementos, pero no los mismos: names() lo muestra.

Si solo se quería vaciarlo, hay que guardar otra cosa, por ejemplo NA.

Cuando cada caso mide distinto

diagnosticos <- list(
  A01 = c("HTA", "DM2"),
  A02 = "asma",
  A03 = c("HTA", "ERC", "anemia")
)
lengths(diagnosticos)      #> A01 2   A02 1   A03 3
diagnosticos$A03[2]        #> "ERC"

Cada paciente tiene un número distinto de diagnósticos. Un data frame exige columnas del mismo largo; una lista, no.

Esta es la razón de fondo para usar listas con datos clínicos: diagnósticos, medicamentos, consultas o resultados de laboratorio que varían de un paciente a otro.

lengths(), con s, da el largo de cada elemento; length() daría 3, el número de pacientes.

El data frame es una lista

nacimientos <- MASS::birthwt

typeof(nacimientos)                #> "list"
length(nacimientos)                #> 10   <- las columnas son sus elementos

class(nacimientos[["bwt"]])        #> "integer"      <- lo que hay dentro
class(nacimientos["bwt"])          #> "data.frame"   <- la caja más chica

Por eso $ y [[ ]] funcionan en los data frames: cada columna es un compartimento de una lista.

Un data frame es una lista con una regla extra: todos sus elementos son vectores del mismo largo. Por eso se imprime como tabla.

Se vuelve a cargar nacimientos para empezar limpio: la práctica de factores le agregó columnas y cambió referencias.

Aquí se explica lo que en data frames se usó sin explicar: nutricion_df$Calorias y nutricion_df[["Nombre"]] son la forma de sacar un elemento de una lista.

Los modelos son listas

nacimientos$smoke <- factor(nacimientos$smoke, levels = c(0, 1),
                            labels = c("no fumó", "fumó"))
modelo <- lm(bwt ~ smoke, data = nacimientos)

typeof(modelo)                  #> "list"
length(modelo)                  #> 13
modelo$coefficients             #> (Intercept) 3056   smokefumó -284
summary(modelo)$r.squared       #> 0.036

lm() devuelve una lista de 13 compartimentos, y summary() devuelve otra.

Es el modelo de «La categoría de referencia»: el peso al nacer según si la madre fumó. Se vuelve a crear el factor porque nacimientos se cargó limpio.

names(modelo) lista los 13 compartimentos: coefficients, residuals, fitted.values, entre otros; uno de ellos, contrasts, guarda cómo se codificó el factor. coef(modelo) es lo mismo que modelo$coefficients: es la función que usamos en factores.

El R² no está en modelo sino en summary(modelo): son dos listas distintas. Si preguntan por qué es tan bajo: fumar explica poco de la variación del peso al nacer.

Todo lo que hagan con un modelo empieza por saber sacar elementos de una lista.

Practica · de vectores a listas

nacimientos <- MASS::birthwt
# bwt: peso al nacer (g) · smoke: 1 = fumó · low: 1 = bajo peso (< 2500 g)
  1. Vector: guarda bwt en peso y cuenta cuántos bebés pesaron menos de 2500 g
  2. Factor: convierte smoke en factor con las etiquetas «no fumó» y «fumó»
  3. Data frame: guarda en fumadoras solo las madres que fumaron, con las columnas age y bwt. ¿Cuántas son?
  4. Matriz: haz la tabla de smoke contra low y saca con [fila, columna] cuántas madres que fumaron tuvieron un bebé con bajo peso
  5. Lista: junta peso, fumadoras y tabla en una lista resumen y saca de ahí la edad de la primera madre que fumó

Doce minutos. Recorre toda la unidad con los mismos datos, en el orden en que cada paso necesita al anterior: vector, factor, data frame, matriz y lista.

Trampas que van a salir:

  • Si alguien se salta el 2, en el 3 smoke == "fumó" compara números con texto: da 0 filas y ningún error.
  • En el 4, low sigue siendo número: las columnas de la tabla se llaman «0» y «1», y se piden entre comillas.
  • En el 5, con un solo corchete, resumen["fumadoras"]$age da NULL: es la trampa de la caja.

Practica · respuestas

peso <- nacimientos$bwt
sum(peso < 2500)                                   #> 59                # 1
nacimientos$smoke <- factor(nacimientos$smoke, levels = c(0, 1),
                            labels = c("no fumó", "fumó"))              # 2
fumadoras <- nacimientos[nacimientos$smoke == "fumó", c("age", "bwt")]
nrow(fumadoras)                                    #> 74                # 3
tabla <- table(nacimientos$smoke, nacimientos$low)
tabla["fumó", "1"]                                 #> 30                # 4
resumen <- list(peso = peso, fumadoras = fumadoras, tabla = tabla)
resumen$fumadoras$age[1]                           #> 20                # 5

En el 1 son 59: los mismos bebés con bajo peso de la tabla de factores (29 + 30).

En el 3 quedan 74 filas y 2 columnas. En el 4 también vale tabla[2, 2], por posición: una tabla de dos variables se selecciona como una matriz.

En el 5 también vale resumen[["fumadoras"]][["age"]][1]. La primera madre que fumó tenía 20 años.

Cierre

La escalera de la unidad

Estructura Guarda Se rompe cuando…
Vector un tipo, una dimensión necesitas filas y columnas
Matriz un tipo, dos dimensiones las columnas son de tipos distintos
Data frame tipos distintos, mismo largo los elementos no miden lo mismo
Lista cualquier cosa — no se rompe, por eso es la última

Y fuera de la escalera, el factor: no es un contenedor, es un vector que sabe a qué categoría pertenece cada dato.

No hay que memorizar cinco estructuras. Hay que reconocer qué te está pidiendo el problema.

Lo que se repitió tres veces

v[v > 30]                             # vector
m[m[, "Calorias"] > 100, ]            # matriz
df[df$Calorias > 120, ]               # data frame
  • La condición devuelve un vector de TRUE/FALSE
  • Ese vector va entre corchetes, y R se queda con lo que valga TRUE

Una sola idea, tres sintaxis. Cerrar aquí y no añadir nada más: si el bloque de listas se comió el tiempo, esta diapositiva sola vale como cierre.
